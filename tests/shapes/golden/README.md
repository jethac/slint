# Golden vector format and tolerance policy

Generated by `../generate.sh` from the pinned androidx sources
(`23327507f7fc7d5b19d65fec4b090f60c970079b`). Every f32 is stored as its
unsigned IEEE-754 bit pattern (u32), so exact bit-for-bit comparison is
possible — and **bit-exactness is the default**: a parity failure means either
a real porting bug or a last-ulp difference between the JVM's intrinsics and
Rust's `libm`/`std` path. The latter must be justified per constructor in the
tolerance table below before being added to the `TOLERANT_*` lists in
`internal/core/tests/shapes_parity.rs`.

## `material_shapes.json`

```json
{
  "pin": "<androidx commit>",
  "shapes": {
    "<name>": {
      "cubics": [[8 × u32] × n],
      "features": [{"kind": "edge"|"corner", "convex": bool, "count": int}],
      "measured_features": [{"kind", "convex", "count", "start_offset": u32}],
      "center": [u32, u32],
      "bounds": [u32 × 4],
      "max_bounds": [u32 × 4]
    }
  }
}
```

`cubics` are the cubic anchor/control points in order
(`anchor0 x/y, control0 x/y, control1 x/y, anchor1 x/y`). `bounds` is
`calculateBounds(approximate = true)`, `max_bounds` is `calculateMaxBounds()`.
`measured_features` is the polygon run through
`MeasuredPolygon.measurePolygon(LengthMeasurer(), …)`; `start_offset` is each
feature's `progress` — the outline-progress offset `FeatureMapping` aligns on.

## `morphs.json`

```json
{"pin": "<androidx commit>", "morphs": {"<from>-><to>": {"<t>": [[8 × u32] × n]}}}
```

with `t` ∈ {0, 0.25, 0.5, 0.75, 1}. The pairs cover every morph class: same
shape (`heart->heart`), convex→convex with equal and very different vertex
counts (`triangle->square`, `square->circle`, `circle_5->cookie_12_sided`),
convex↔concave (`triangle->heart`, `heart->square`, both cookie pairs),
rounded↔sharp (`star_default->pill_2x1`, `pill->pill_star_8`), and concave
with many vertices (`burst->oval`, `cookie_7_sided->clover_8_leaf`).

## `svg_paths.json`

```json
{"pin": "<androidx commit>",
 "paths": {"<name>": {"path": "<d>",
                      "features": [{"kind", "convex", "count"}],
                      "cubics": [[8 × u32] × n]}}}
```

`cubics`/`features` are the `SvgPathParser.parseFeatures` output flattened —
the raw parsed cubics plus the closing cubics `RoundedPolygon` adds and the
orientation `PolygonValidator.fix` enforces. `material_favorite` and
`material_eco` are the Material Symbols paths from upstream's
`SvgPathParserTest`; `absolute_arc` exercises elliptical arcs.

## Tolerance table

Bit-exact by default. A constructor/morph/path may only be added here (and to
the matching `TOLERANT_*` list in `shapes_parity.rs`) with a measured
last-ulp justification:

| Golden entry | Max abs diff observed | Reason |
| ------------ | --------------------- | ------ |
| `triangle` (interpreter) | 1.19e-7 | `Shapes.rotated` rotates about the shape center in f32 where Kotlin `Matrix().apply { rotateZ(..) }` rotates about the origin with f64 trig narrowed to f32; both outputs are then re-normalized, leaving last-ulp residue |
| `puffy` (interpreter) | 5.96e-8 | `Shapes.scaled` scales about the shape center where Kotlin `scale()` applies about the origin; re-normalized afterwards |
| `cookie_7_sided` (interpreter) | 1.19e-7 | same `Shapes.rotated` path as `triangle` |
| `cookie_9_sided` (interpreter) | 1.19e-7 | same `Shapes.rotated` path as `triangle` |
| `cookie_12_sided` (interpreter) | 5.96e-8 | same `Shapes.rotated` path as `triangle` |

Structure (cubic counts, feature kind/convexity/count, feature start-offset
order, centers) is always compared exactly, tolerance or not.
